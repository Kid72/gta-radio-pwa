# Аудит порядка треков (2026-10-30)

Проверка, совпадает ли `src/data/track-timings.json` с тем, что реально звучит
в раздаваемых лупах. Метод: хрома CQT + NCC Пирсона против официальных 30-секундных
превью Deezer, leave-one-out внутри станции. AcoustID/Chromaprint не использовался.

## Итог

- 382 music-cue на 17 станциях; 303 с найденным превью (79.3%).
- Свой трек на месте: **66** (21.8%), лучший из всех превью станции: **60** (19.8%).
- На месте cue звучит **другой** трек той же станции: **97** (45 из них со скором ≥0.90).
- Нет матча ни к одному превью: **140**.
- Вердикты: **2** «order consistent» (rebel-radio, k-rose), **13** «order suspect»,
  **2** «unverifiable» (if99, fusion-fm).

## Что читать

- `report.md` — полный отчёт: метод, пороги, таблица по станциям, разбор,
  ограничения и чего не хватает для 100% подтверждения.
- `report.json` — данные по каждому cue (`own`, `own_rank`, `runner_up`, `margin`, `z`,
  `best_other`, совпадение Deezer) и сводки по станциям.
- `scripts/` — пайплайн, порядок запуска описан в конце `report.md`.

## Важное ограничение

30-секундное превью может не пересекаться с проверяемым окном трека, поэтому
`no_match` означает «не проверили», а не «неправильно». Полное подтверждение требует
AcoustID-ключа или полных треков вместо превью.
